# URP 外观上的差异

迁移后的有些差异既不是损坏，也不是转换错误：URP 只是把同样的材质画得与 Built-in 略有不同。差异足够大时，场景比较会把它们
标为“有变化”，因此值得了解。

## Standard 到 URP Lit

![展台 STD01：Standard 与 URP Lit 并排](../images/STD01.jpg)

Unity 自己的 Standard 到 URP Lit 转换会略微改变高光和反射：URP 的反射模型和环境反射不同。在我们的测试场景中，最多约 7 %
的画面不同。Urpify 的“相同”和“有变化”阈值正是以这个转换为基准校准的，因此单凭它不会让场景变成“有变化”。

## 额外光源

Built-in 用各自的叠加 Pass 绘制每个额外光源，URP 则在一个 Pass 中把它们相加，并使用自己的衰减曲线和每物体光源数量上限
（可在 URP Asset 中设置）。点光源很多的场景看起来会略有不同，超出每物体上限的光源会被 URP 舍弃。

## 泛光

URP 的泛光比 Post-processing Stack v2 把小亮点扩散得更宽、更柔和。Urpify 迁移泛光参数时会做校准，让光晕更接近，但不会
完全相同；其余差异来自不同的泛光金字塔，没有参数可以复现。

## Unity 6 播放器中的环境光

从天空盒获取环境光、但没有烘焙光照数据的场景，在 Unity 6 的播放器中会比在编辑器中更暗，Built-in 和 URP 都是如此。这不是
迁移造成的，但在把迁移后的播放器与编辑器对比时会注意到。扫描会报告这种情况（“天空盒环境光未烘焙”），场景面板中的
**烘焙环境** 按钮只烘焙环境光和反射，并做备份。

## 使用 Opaque Texture 的 GrabPass

使用默认的 GrabPass 来源时，折射中看不到透明对象：URP 在绘制它们之前复制屏幕。若要与 Built-in 一致，请将 GrabPass 来源
设为“透明对象之后”。参见 [GrabPass](constructs/grabpass.md)。

## 透明对象与排序

URP 对透明对象的排序方式相同，但会在所有物体的前两个 Pass 之后，才绘制转换后着色器的额外 Pass（第三个及以后），这可能
改变重叠透明对象的顺序。参见 [额外 Pass](constructs/extra-passes.md)。
