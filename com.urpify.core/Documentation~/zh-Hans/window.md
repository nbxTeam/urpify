# Urpify 窗口

`Window > Rendering > Urpify`。窗口本身的文字尽量简短；本页解释其图标、计数和标签的含义。把鼠标悬停在窗口中的任意图标或
计数上，也会显示同样的说明。

## 严重程度图标

每个图标都有自己的形状，因此颜色从来不是唯一的提示。

| 图标 | 名称 | 切换到 URP 后会怎样 |
|---|---|---|
| 实心方块（粉色） | 渲染为粉色 | 物体用 URP 的错误着色器渲染。在发布构建中不可见。 |
| 实心三角（琥珀色） | 无报错地损坏 | 没有错误也没有粉色，但效果消失或出错：传送门变成灰色的墙、水失去泡沫、后期效果消失。 |
| 实心菱形（蓝色） | 外观不同 | 能渲染，但有可见的差异，例如场景变暗。 |
| 圆环（灰色） | 无可见变化 | 无需处理，或 Unity 转换器可直接处理。 |

列表中的行、场景和资源显示其最严重发现的图标。

## 工具栏下方的条

按有名称的分组显示数量。迁移前是 `场景` 和 `资源`，每组后面跟着每种严重程度的图标和数量：有多少场景包含该严重程度的物体，有多少资源具有该严重程度。场景或资源会在其所属的每个类别中计数，因此数字会有重叠。捕获之后，`已捕获` 会补充画面显示的结果：新的粉色、有变化、无变化。迁移后第一组是 `结果`：已修复、待检查、待处理。每个数字都是按钮：选择它，列表就只显示它所计数的内容；再次选择即可显示全部。把鼠标悬停在数字上可查看它计数的内容，悬停在 `上次扫描` 上可查看扫描的文件数和耗时。

## 场景的判定

一个场景有两个判定：

- **静态**，来自扫描：场景使用的所有内容中最严重的问题。粉色物体可能不在任何捕获的画面中，因此静态的粉色可能与观测的
  “相同”并存。
- **观测**，来自迁移前后的捕获：最差的一帧。每帧显示变化像素的比例和迁移后粉色像素的比例；把鼠标悬停在该行上可查看平均
  差异和迁移前的粉色比例。一个较大的变化区域（反射消失、光晕消失）即使总体变化的像素很少，也会让该帧成为“有变化”。迁移后
  场景运行时 Console 中出现的错误同样会让它成为“有变化”，并显示第一条错误。如果扫描预计会出现迁移未修复的无提示损坏（仅
  使用 Unity 转换器、用免费包处理只有 Pro 才能修复的损坏，或 Urpify 无法转换的损坏），而画面看起来仍然相同，面板会提示
  这一点：请查看差异图。

在迁移前后视图中，线的左侧是迁移前，右侧是迁移后。`显示差异` 会标出变化的像素：变化越大，像素越红。

## 由谁修复

概览按由谁修复来统计损坏的资源：

- **Unity 转换器和 Urpify**：Unity 的 Render Pipeline Converter，以及 Urpify 随后运行的修复（都在免费包中）。
- **Urpify Pro**（在免费包中显示为带锁的 **需要 Pro**）：只有 Pro 转换器才能转换的着色器、脚本和组件。
- **手动或暂不支持**：项目在迁移前就已损坏、该结构在 URP 中没有对应物，或 Urpify 暂不转换。发现中会说明怎么做。

列表中的行说明由谁修复该资源：`Unity`（Unity 转换器）、`Urpify`（免费修复）、`Pro`（Urpify Pro；在免费包中显示锁和 `Pro`）、`手动`。提示中说明结果有多接近：与原版一致、接近原版，或已转换但看起来不同（请检查）。`由谁修复` 筛选器选择相同的分组。迁移后，这一列改为说明资源的结果：`已修复`、`待检查` 或 `待处理`。在“Urpify 转换器”这一步之前，这是扫描的预期；之后是这一步实际做的事。报告保留转换器自己的等级（`自动`、`近似`、`检查`、`暂不支持`、`手动`）。

Urpify 转换的着色器会通过渲染进行检查：转换前，用项目中使用该着色器的材质贴在一个球体上，在 Built-in 中渲染；转换后在 URP
中渲染，然后比较两者。若球体有很大一部分不同，着色器仍会被转换，但不会标为 `自动`：而是 `检查`，两张图片放在
`Urpify/Reports/self-check/`。“很大一部分”指超过球体的 25 %：Unity 自己的 Standard 到 URP Lit 转换会让深色、高饱和的颜色
变化约 20 %，这就是 URP Lit 的样子，不是错误。粉色，或遮挡了后方物体并显示相机清除色的物体，无论大小都标为 `检查`。

有些着色器无法在球体上判断，最多只能是 `近似`，原因写在报告中；请在场景比较中检查它们：

- 没有材质的屏幕效果（脚本把它应用到整个画面）；
- `Hidden/` 下的内部着色器（脚本用自己的数据绘制它）；
- 读取时间（`_Time`）的着色器：Built-in 渲染在转换前完成，URP 渲染在转换后完成，因此显示的是动画的不同时刻（只计入粉色
  或渲染变暗的情况）。

在 Unity 2022.3 中，带 `GrabPass` 的着色器用 Game 类型的隐藏相机而不是预览相机渲染：URP 14 不为预览相机提供 Opaque
Texture。这样的相机也会运行你的 URP Asset 中的渲染器功能。

## 显示会坏掉什么

概览中以及迁移窗口步骤上方的 `显示会坏掉什么`，会在你修复任何东西之前，展示仅靠 URP 时项目会变成什么样：备份项目、在 Built-in 中捕获场景、安装 URP、运行 Unity 转换器、再次捕获场景并打开结果。Urpify 自己的修复还没有运行。然后选择 `用 Urpify 修复`（Urpify 转换器、重新捕获和报告）或 `回滚`。在免费包中修复的是免费的部分，结果会说明哪些需要 Urpify Pro。

## 步骤的顺序

前面的步骤没有完成时，后面的步骤不能运行，并在说明下方显示原因：迁移前捕获需要备份，Unity 转换器需要已安装的 URP，Urpify 转换器需要先运行 Unity 转换器（使用 Keep Built-in support 时除外，此时项目保留在 Built-in），迁移后捕获需要迁移前的画面和一个用 URP 渲染的项目。用同一个管线拍的两次捕获不会被比较：结果会说明没有可比较的内容。

## 迁移后的结果

Unity 转换器运行之后，右侧不再显示概览，而是显示结果：用一行说明最重要的事（例如 `完成。场景看起来和切换前一样`），变化最大的场景的迁移前后对比，然后只列出需要你处理的事项，每项都有按钮，已修复的资源折叠在 `已自动修复` 下。每一步之后窗口都会重新扫描项目，所以列表会显示哪些已修复、哪些还剩下。Urpify 添加到项目中的文件（`Assets/Urpify/`、包中的 `UrpCompat` 文件夹、`UrpSettingsCheck_*` 脚本）不会出现在列表中。

## 比较场景

每个捕获的场景及其结果的文字说明。选择一个场景即可在原处用滑块比较它的画面；`打开场景` 会打开该场景。只有一个场景时，比较一开始就是打开的。即使之后又扫描过，窗口也始终显示最近一次比较。画面按屏幕显示的样子保存，不带透明度，默认使用 Game 视图的尺寸，除非设置中的 `捕获尺寸` 另有指定。

## 许可证标签

文件头中写明许可证（如 `MIT` 或 `CC-BY-NC-4.0` 等 SPDX 标识符）的着色器，会在名称旁以标签显示。转换后的副本属于衍生作品，
受同一许可证约束。非商业许可证（`-NC`）以琥珀色标签显示：此类着色器的转换副本不得出售。

## 环境光（场景面板）

在 Unity 6 中，对于从天空盒获取环境光且没有烘焙光照数据的场景，播放器渲染时没有这部分光，Built-in 和 URP 都是如此，因此
场景看起来比编辑器中暗。这不是迁移造成的，所以该发现仅供参考（圆环图标）。（在 Unity 2022.3 中，即使没有烘焙数据播放器也
能获得环境光，Urpify 不会报告这些场景。）`烘焙环境` 只把天空盒的环境光和反射烘焙进场景的光照数据（不烘焙光照贴图，并为该
场景关闭 Auto Generate），使播放器与编辑器一致。烘焙前会先备份项目；在同一位置点击 `回滚烘焙`，或在迁移窗口中回滚，即可
撤销。
