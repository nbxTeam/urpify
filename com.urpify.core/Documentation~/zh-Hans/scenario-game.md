# 迁移游戏

你有一个使用 Built-in Render Pipeline 的游戏，想把它迁移到 URP，并保持外观不变。

## 开始之前

- 提交项目。Urpify 会备份它改动的内容，但提交才是你最信任的恢复点。
- 确认项目在 Built-in 下能编译并进入 Play Mode。Urpify 会把脚本编译错误作为一项发现报告：它们会阻止 Play Mode，从而也
  阻止捕获。
- 决定要对比哪些场景：Project Settings > Urpify > 比较 > 场景。默认是 Build Settings 中的场景。
- 在效果很关键的场景中放置几个 Migration Viewpoint：传送门、镜子、水、后期效果。把 `MigrationViewpoint` 组件添加到一个
  空 GameObject 上，像相机一样调整朝向。它带有 EditorOnly 标签，永远不会进入构建。

## 扫描并阅读概览

Window > Rendering > Urpify > **扫描项目**。概览先列出会损坏的场景，然后按由谁修复来统计损坏的资源：

- **Unity 转换器和 Urpify**：Unity 的 Render Pipeline Converter 会升级的内置着色器，以及其结果有误、由免费包随后修复的
  情况。
- **Urpify Pro**：自定义着色器、图像效果、相机脚本、命令缓冲区和投影器。
- **手动或暂不支持**：项目在迁移前就已损坏、URP 中没有对应结构，或 Urpify 暂不转换。参见
  [哪些内容不会被转换](not-converted.md)。

左侧列表可以按问题、修复方式和类型筛选，也可以按文件名或规则 ID 搜索。**无需 Pro 即可修复** 显示免费包能处理的内容。

## 迁移

**迁移...** > **全部运行**，或逐步运行。会改动文件的步骤会先做备份。步骤运行时，窗口会显示进度，任何步骤都可以重新运行。
如果编辑器在某一步中途关闭，下次打开窗口时会提示你重新运行该步骤或将其回滚。

## 对比与检查

**迁移后捕获并比较** 完成后，打开 **比较场景**：

- **相同**：画面在以 Standard 到 URP Lit 的转换为基准校准的阈值内一致。
- **有变化**：部分像素不同，或某个区域变化很大（反射消失、光晕消失），或场景运行时记录了错误。
- **新的粉色**：某个物体以错误着色器渲染。

用 **显示差异** 查看每个有变化的场景。有些差异来自 URP 本身，而不是迁移：参见 [URP 外观上的差异](urp-differences.md)。

最终报告（**总结**）列出每个已转换的文件及其等级：`自动`（几乎完全一致）、`近似`（接近，但并非逐像素一致）、`检查`
（已转换，但 Urpify 自己的测试渲染与原版不同：请检查），以及需要手动处理的内容。

## 回滚

**全部回滚** 会把项目恢复到第一步之前的状态。在某一步上点 **回滚到此处** 会撤销其后的所有步骤。迁移之后你自己改动的
文件保持原样，并在 Console 中列出。

## 在构建流水线中

每个步骤都可以从命令行运行，因此构建服务器可以迁移一个分支，并在场景变成粉色时让构建失败。参见 [命令行](cli.md)。
