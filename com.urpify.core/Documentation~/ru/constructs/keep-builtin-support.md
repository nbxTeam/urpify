# Сохранить поддержку Built-in: один шейдер для обоих конвейеров

Результат = **Сохранить поддержку Built-in** (Project Settings > Urpify > Перевод, Pro) записывает каждый переведённый
шейдер одним файлом, который работает и в Built-in, и в URP. Это для авторов Asset Store, чьи покупатели сидят на любом из
конвейеров, и для проектов, которые меняют конвейер в зависимости от платформы.

## Как устроен файл

```
Shader "Author/Water" {
    Properties { ... }                      // без изменений
    SubShader {                             // добавлен Urpify, первым
        Tags { "RenderPipeline" = "UniversalPipeline" }
        PackageRequirements { "com.unity.render-pipelines.universal" }
        ...                                 // переведённые проходы
    }
    SubShader { ... }                       // исходный SubShader Built-in, байт в байт
    Fallback "..."
}
```

Unity выбирает первый SubShader, подходящий к активному конвейеру. При активном URP берётся SubShader для URP; в Built-in
он пропускается из-за тега, и берётся оригинал. `PackageRequirements` не даёт проекту Built-in без URP вообще компилировать
часть для URP. Проверено на Unity 6000.5 и 2022.3.

Исходные SubShader не трогаются, поэтому материал в Built-in рисуется точно как раньше. Это проверено байт в байт: каждый
шейдер стенда, переведённый с «Сохранить поддержку Built-in», рисует в Built-in ту же картинку, что и оригинал.

## Что ещё меняется с этим результатом

- Материалы остаются на своих шейдерах, поэтому одни и те же материалы работают в обоих конвейерах.
- `Shader.Find` с именем встроенного шейдера в скрипте выбирает имя во время работы скрипта, по активному конвейеру.
- Переведённые скрипты и Renderer Feature работают только в URP и в Built-in ничего не делают.

## Цена

Шейдер с двумя SubShader компилирует оба, поэтому у сборки с ним больше вариантов. Размер и время сборки с шейдерами для
обоих конвейеров измерены на стенде: см. [Вопросы и ответы](../faq.md).
