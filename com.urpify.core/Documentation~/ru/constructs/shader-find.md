# Shader.Find с именами встроенных шейдеров

![Стенд C04: материал, созданный в коде через Shader.Find("Standard"), розовый после конвертера Unity, исправлен Urpify](../../images/C04.jpg)

*Стенд C04: скрипт во время игры создаёт материал через `new Material(Shader.Find("Standard"))` и задаёт `_Color`.*

## Что ломается

Конвертер Unity переводит файлы материалов, а не код. Скрипт, который создаёт материал через `Shader.Find("Standard")`,
`"Diffuse"`, `"Legacy Shaders/..."` или другое имя встроенного шейдера, получает шейдер, который URP нарисовать не может,
и объект розовый. Имена свойств, которые задаёт скрипт (`_MainTex`, `_Color`, `_Glossiness`), в URP Lit — скрытые свойства,
поэтому даже после ручной замены шейдера эти вызовы ничего не меняют.

Находки: `Shader.Find("...")` (`SCRIPT.SHADER_FIND_BUILTIN`), «Имена свойств Built-in в коде»
(`SCRIPT.BUILTIN_PROPERTY_NAMES`).

## Что делает Urpify (Free)

Это одно из исправлений после конвертера Unity, в бесплатном пакете. В том же скрипте:

- имя шейдера становится шейдером URP, который конвертер Unity выбирает для этого встроенного шейдера (`Standard` в
  `Universal Render Pipeline/Lit`), или ближайшим шейдером URP из таблицы Urpify для шейдеров без правила перевода Unity;
- имена свойств, которые задаёт тот же метод, становятся именами URP (`_MainTex` в `_BaseMap`, `_Color` в `_BaseColor`).

С результатом «Сохранить поддержку Built-in» каждое имя выбирается во время игры по активному конвейеру, поэтому скрипт
продолжает работать и в Built-in.

Переписанный скрипт компилируется до сохранения; если он не компилируется, оригинал возвращается и попадает в отчёт.
