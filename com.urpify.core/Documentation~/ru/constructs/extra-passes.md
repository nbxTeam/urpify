# Дополнительные проходы: обводки, оболочки, слои

![Стенд S12: toon-шейдер с проходом обводки инвертированным корпусом](../../images/S12.jpg)

*Стенд S12: toon surface-шейдер с написанным вручную проходом обводки. Только после конвертера Unity от него остаётся
одна обводка вокруг розовой сферы.*

## Что ломается

URP рисует у объекта не больше двух проходов SubShader: один `SRPDefaultUnlit` и один `UniversalForward`, в таком порядке.
Built-in рисует каждый проход. У шейдера с проходом обводки рядом с проходом освещения, у оболочек меха, слоёв штриховки
или двух проходов без тега LightMode остаётся только один из них — часто молча.

Находки: «Дополнительные проходы рядом с surface-программой» (`SHADER.SURFACE.EXTRA_PASS`), «Проходов без LightMode: N»
(`SHADER.PASS.MULTIPLE_UNTAGGED`).

## Что делает Urpify (Pro)

- **Два рисуемых прохода:** первый становится `SRPDefaultUnlit`, второй `UniversalForward`, так что порядок рисования
  Built-in сохраняется. Проверено на URP 14 и 17.
- **Три и больше рисуемых проходов:** проходы с третьего получают теги `UrpifyPass3`, `UrpifyPass4` и так далее. Renderer
  Feature Built-in Camera Hooks от Urpify рисует их после непрозрачных или прозрачных объектов URP, проходы каждого
  объекта по порядку. До 32 рисуемых проходов на SubShader.
- **Написанные вручную проходы рядом с surface-программой** сохраняются как есть и переводятся по правилам vert/frag.
- Шейдеры экранных эффектов, которые рисует `Graphics.Blit`, тегов не получают: их проходы выбираются по индексу.

Renderer Feature добавляется в каждый рендерер URP, которому он нужен, на шаге «Конвертеры Urpify».

## Насколько близко

`Авто` для двух проходов, `Авто, приблизительно` для трёх и более. Если на экране несколько таких объектов, первые два
прохода каждого объекта рисуются до дополнительных проходов любого объекта, что может изменить сортировку
перекрывающихся объектов.
