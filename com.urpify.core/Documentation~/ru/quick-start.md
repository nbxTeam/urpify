# Быстрый старт

Весь цикл за 5 минут: сканирование, миграция, сравнение. Сначала попробуйте на демо-сцене, потом на копии своего
проекта.

## 1. Установка

Установите в проект, который ещё на встроенном конвейере:

- **Urpify Pro:** один файл, `Urpify-Pro-1.0.0.unitypackage` (из Asset Store: Package Manager > My Assets > Import). Assets > Import Package > Custom Package, импортируйте всё: в файле Urpify, Urpify Pro, демо и эта документация.
  Бесплатный Urpify уже установлен из `.unitypackage` — импортируйте Pro поверх, удалять ничего не нужно. Установлен через
  Package Manager — сначала удалите его там (Package Manager > Urpify > Remove): Urpify Pro уже содержит его.
- **Urpify (бесплатный):** `Urpify-1.0.0.unitypackage` из [GitHub Releases](https://github.com/nbxTeam/urpify/releases/latest),
  импорт так же, или Package Manager > `+` > Add package from git URL:
  `https://github.com/nbxTeam/urpify.git?path=com.urpify.core#v1.0.0`.

Перед миграцией закоммитьте проект в систему контроля версий. Urpify делает бэкап каждого изменяемого файла, но коммит —
самая надёжная точка восстановления.

## 2. Откройте демо (по желанию)

Help > Urpify > **Import Demo** или **Импортировать демо** в пустом окне Urpify. Демо попадёт в `Assets/Samples/Urpify/1.0.0/Demo`, его сцена
откроется. При установке через Package Manager то же делает Package Manager > Urpify > Samples > **Demo** > Import. В сцене по
стенду на каждую конструкцию, которая ломается в URP: surface-шейдеры, освещённый vert/frag-шейдер, стекло с GrabPass,
вода, читающая глубину, проектор, зеркало, материал из кода и стекло в режиме Standard Transparent. У каждого стенда
есть Migration Viewpoint, поэтому сравнение показывает каждый крупно.

## 3. Сканирование

Window > Rendering > **Urpify**, затем **Сканировать проект**.

Сканирование только читает файлы. Список слева показывает каждый шейдер, скрипт, материал, сцену и настройку, которые
ломаются в URP, по группам. У каждой строки есть значок:

- закрашенный квадрат: станет розовым;
- закрашенный треугольник: сломается без ошибки (портал станет стеной, вода потеряет пену, эффект пропадёт);
- закрашенный ромб: будет выглядеть иначе;
- кольцо: без видимых изменений.

Выберите строку, чтобы увидеть, что ломается, почему и кто это исправит. Шейдер открывается в панели шейдера: его код
до и после перевода и превью в Built-in и URP рядом.

## 4. Миграция

Нажмите **Миграция...**. Окно перечисляет шаги:

1. **Сканирование**: то же сканирование, только чтение.
2. **Бэкап**: копирует ассеты, настройки и список пакетов проекта в `Urpify/Backup`.
3. **Снимки «до»**: запускает каждую сцену в Play Mode и сохраняет кадры основной камеры и всех Migration Viewpoint.
4. **Установка URP**: добавляет версию URP, которая идёт с вашим редактором.
5. **Конвертер Unity**: Render Pipeline Converter от Unity с обходами, которые нужны, чтобы он работал надёжно.
6. **Конвертеры Urpify**: чинят то, что конвертер Unity оставляет сломанным. С Pro также переводят шейдеры, скрипты и
   компоненты.
7. **Снимки «после» и сравнение**: те же кадры в URP, сравнённые с кадрами «до».
8. **Итог**: итоговый отчёт.

Нажмите **Выполнить все**. Каждый шаг можно выполнить и отдельно, и каждый можно откатить: **Откатить до этого шага** у
шага или **Откатить все**.

## 5. Сравнение

Нажмите **Сравнить сцены**. Для каждой сцены видны кадры до и после со шторкой между ними. **Показать различия** отмечает
изменённые пиксели: чем краснее, тем сильнее изменение. **Только изменившиеся** скрывает сцены, которые выглядят так же.

В главном окне у сцены два вердикта: **по сканированию** и **по снимкам**. Розовый объект может не попасть ни в один
снятый кадр, поэтому вердикт по сканированию бывает хуже, чем по снимкам. Добавьте Migration Viewpoint (пустой
GameObject с компонентом `MigrationViewpoint`) там, где хотите посмотреть ближе, и снимите заново.

## 6. Готово или откат

**Отчёт** > Экспорт HTML даёт отчёт, который можно отправить команде. Если результат не нравится, **Откатить все**
возвращает каждый файл, изменённый миграцией, и переносит созданные ею файлы в бэкап. Файлы, появившиеся между шагами,
не трогаются, поэтому ваша собственная работа сохраняется.
Сразу после отката в окне Unity перезапускается, чтобы загрузить проект таким, какой он на диске.
