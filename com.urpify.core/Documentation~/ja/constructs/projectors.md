# プロジェクター

![ブース C01：プロジェクターの影のしみ。Unity のコンバーター後は消え、Urpify の後は戻る](../../images/C01.jpg)

*ブース C01：`Projector` コンポーネントが立方体の下に影のしみを投影します。Unity のコンバーターだけを通すと、影はありま
せん。*

## 何が壊れるか

URP は `Projector` コンポーネントを描画しません。影のしみ、選択リング、投影デカールは何の知らせもなく消えます。

検出結果：「... の Projector」（`SCENE.PROJECTOR`）、「プロジェクターのシェーダー」（`SHADER.PROJECTOR`）。

## Urpify の対処（Pro）

`Projector` はプロジェクターのまま、シェーダーもそのままです。Urpify の Built-in Camera Hooks レンダラー機能が、有効な
各プロジェクターのマテリアルを、その視錐台とレイヤー内のレンダラーに描画します。`unity_Projector` と
`unity_ProjectorClip` は Built-in と同じくオブジェクトごとに設定されます。サイズ、向き、範囲、無視するレイヤー、マテリアル
はコンポーネントから取るので、プロジェクターはこれまでどおり編集できます。

この機能は毎フレームシーンを検索する代わりに、プロジェクターとそれが届くレンダラーをキャッシュします：プロジェクターは
30 フレームごと、レンダラーは 60 フレームごと、どちらもシーンの読み込みと解放のときに更新します。レンダラーは各プロジェ
クターとカメラの視錐台で絞り込みます。Unity 6.5 でプロジェクター 1 つの測定：レンダラー 88 個で 1 フレームあたり
0.02 ms。レンダラーを 5000 個追加すると、すべてがカメラの前にある場合は約 2.2 ms、後ろにある場合は 0.09 ms です。

プロジェクターとそのシェーダーは何も変わらないため、「Built-in 対応を残す」でエクスポートしたパッケージは両方の
パイプラインで動き続けます。

## どこまで近いか

`自動（近似）`：同じオブジェクトに同じシェーダー。URP 自身の Decal Projector は使わないため、見た目は Built-in のままです。
