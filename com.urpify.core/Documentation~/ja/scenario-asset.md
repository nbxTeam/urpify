# Asset Store パッケージを両方のパイプライン向けに変換する

Asset Store でシェーダーやエフェクトを公開していて、Built-in と URP の両方の購入者に使える 1 つのパッケージにしたい場合の
手順です。主な操作は **Built-in と URP 向けにエクスポート**（Pro）です。

## 必要なもの

- URP がインストールされたプロジェクト。変換したシェーダーは書き出す前に URP 向けにコンパイルされるので、URP がないと
  エクスポートは実行されません。パッケージ自体は Built-in のパッケージのままでかまいません。プロジェクトはエクスポートを
  行う場所にすぎません。
- 現在配布している `.unitypackage`。

## パッケージを分析する

Urpify ウィンドウで **変更**（スコープ）> **Unity パッケージ（.unitypackage）...** を選び、ファイルを選択します。Urpify は
それを一時フォルダーにインポートしてスキャンし、ウィンドウを閉じるかスコープを変えたときにフォルダーを削除します。
プロジェクトは元のままです。

概要には、URP の購入者にとって何が壊れるかが、プロジェクトと同じ形で表示されます。無料パッケージはここまでです：
レポート（レポート > HTML をエクスポート）を見せたり添付したりできます。

## エクスポート

概要の **Built-in と URP 向けにエクスポート...**、またはレポート > **変換済みパッケージをエクスポート...** を選び、保存先を
指定します。新しい `.unitypackage` は元のすべての GUID とパスを保ち、次のものを含みます。

- 変換したシェーダー。出力 **Built-in 対応を残す**（Project Settings > Urpify > 変換 > 出力）では、各ファイルが元の
  Built-in の SubShader をそのまま保ち、その前に URP の SubShader を持つので、1 つのファイルが両方のパイプラインで
  動きます。Unity はアクティブなパイプラインに合う SubShader を選びます。
- Unity の組み込みシェーダーを使っていたマテリアル。購入者のプロジェクトで Unity のコンバーターが行うのと同じように更新
  し、そのあとに Urpify の修正を加えます。
- プロジェクトと同じように変換したスクリプト。それぞれ書き出す前にプロジェクトに対してコンパイルします。書き換えが
  コンパイルできないスクリプトは元のまま残され、一覧に載ります。
- Urpify のシェーダーライブラリと小さなランタイム部分。パッケージの各ルートフォルダー内の `UrpCompat` フォルダーに
  置かれ、エクスポートのたびに新しい GUID が付き、ランタイムはパッケージの名前空間に入ります。作者の異なる 2 つの
  パッケージが互いのコピーを共有したり上書きしたりすることはありません。
- パッケージ名を付けた小さなエディターチェック。購入者のプロジェクトが URP を使う場合、シェーダーに必要なもの（Depth
  Texture、Opaque Texture、Built-in Camera Hooks レンダラー機能）を URP Asset で確認し、何かをオンにする前に 1 回だけ
  尋ねます。Built-in では何もしません。

パッケージの隣には互換性レポートが保存されます：シェーダーごとの結果と、購入者に必要な URP Asset の設定。

## 購入者の立場で確認する

エクスポートしたパッケージを、まっさらな Built-in プロジェクトと、まっさらな URP プロジェクトにインポートします。
Built-in では、出力「Built-in 対応を残す」は元とまったく同じに描画されます：元の SubShader には手を加えないためです。
URP では、パッケージのデモシーンを開いて Built-in のスクリーンショットと比べるか、移行のシーン比較をそこで実行します。

## 再配布

変換したシェーダーと `UrpCompat` フォルダーは、有料パッケージに含めて配布できます。
[変換したシェーダーの再配布](../license-redistribution.md)（英語）を参照してください。
