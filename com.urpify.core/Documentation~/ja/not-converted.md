# 変換されないものとその理由

Urpify は、変換しないものをすべて、移行を始める前に理由付きで一覧にします。以下の各項目は 3 つのグループのいずれかに
属します。

- **手動：移行前からプロジェクトが壊れていた。** Urpify はプロジェクト自体のエラーは直しません。何が壊れていて、まず
  何をすべきかを伝えます。
- **手動：変換するものがない。** URP に対応するものがありません。URP のソースで確認済みです。
- **未対応。** 可能ですが、このバージョンの Urpify は行いません。次に取り組む内容です。それまでに手作業で何をすべきかは
  検出結果に書かれています。

開発者が見ていないシェーダーでの独立したテストで測った、Urpify が変換できるシェーダーの割合は製品ページに記載しています。
このページでは、変換されないものとその理由を挙げます。

## 移行前からプロジェクトが壊れていた

| ケース | 表示される内容 | 対処 |
|---|---|---|
| 組み込みパイプラインでシェーダーがコンパイルできない | 「シェーダーがすでにコンパイルに失敗している」 | まず Built-in でのコンパイルエラーを直してください。オブジェクトはすでにピンクです。 |
| プロジェクトのスクリプトがコンパイルできない | 「プロジェクトのスクリプトがコンパイルできない」 | まずこれを直してください：Play Mode、キャプチャ、スクリプトを書き換えるステップを妨げます。古いプロジェクトでは、廃止された API の呼び出しを更新する必要があることがよくあります。 |
| シェーダーがプロジェクトにないファイルを include している | 「include が見つからない」 | ファイルを追加するかパスを直して、もう一度スキャンしてください。 |
| `UsePass` がプロジェクトにないシェーダーを指している | 「UsePass ...：シェーダーが見つからない」 | シェーダーを追加するか、`UsePass` の行を削除してください。オブジェクトは Built-in でもピンクです。 |
| レンダラーがプロジェクトにないマテリアルを参照している | 「... 個のレンダラーでマテリアルが見つからない」 | マテリアルを割り当てるか、見つからないマテリアルやパッケージを戻してください。Unity がパッケージ（ProBuilder など）を更新し、古い既定のマテリアルがなくなったときに起こります。 |

## 変換するものがない

| ケース | 理由 |
|---|---|
| 組み込みレンダラーの内部シェーダー：`Internal-DeferredShading`、`Internal-DeferredReflections`、`Internal-ScreenSpaceShadows`、`Internal-DepthNormalsTexture`、`Internal-MotionVectors`、`Internal-PrePassLighting`、`Internal-Flare`、`Internal-Halo` とそのコピー | Built-in はこれらを Graphics Settings の組み込みシェーダースロットから実行します。URP はそのスロットを読みません：URP 14.0.12 と 17.5.0 のソースは `GraphicsSettings.GetCustomShader` を一度も呼ばず、`BuiltinShaderType` も使いません。URP はディファードライティング、影、depth-normals、モーションベクターを独自のシェーダーで描画します。 |
| LightMode が `Deferred`、`PrepassBase`、`PrepassFinal` のパス | Built-in のディファードとレガシーディファードの経路です。URP はオブジェクトをフォワードパスで描画し、Urpify はそれをシェーダーのフォワードパスから作ります。 |
| サーフェスシェーダーの `finalgbuffer:` 関数 | Built-in のディファード G バッファーパスでのみ実行されます。変換後のフォワードシェーダーは呼びません。 |
| `Camera.depthTextureMode` | URP は無視します。URP は深度テクスチャと法線テクスチャを URP Asset の設定に従って作り、シェーダーが読むときは Urpify がそれをオンにします。 |

## 未対応

| 構成要素 | 現在の動作 | 手作業での対処 |
|---|---|---|
| `Light.AddCommandBuffer` を使うエフェクト（ボリュームライトなど） | URP ではエフェクトが表示されません。フレームの残りは描画されます。 | ライトのコマンドを `BeforeRenderingShadows` または `AfterRenderingShadows` のレンダラー機能に移してください。URP はシャドウマップを別の方法で描画するので、コマンドが何を前提にしているか確認してください。 |
| `OnRenderImage` がカメラの描画、コンピュートのディスパッチ、その他の即時描画に到達するイメージエフェクト | URP ではエフェクトが欠け、フレームの残りは描画されます。 | その呼び出しをエフェクトの外に移します：`OnPreRender`、または `ImageEffectGraphics.ExecuteCommandBuffer` で実行するコマンドバッファーへ。 |
| シェーダーが Built-in の G バッファー（`_CameraGBufferTexture0-3`：スクリーンスペース反射など）を読むイメージエフェクト | URP ではエフェクトが欠け、フレームの残りは描画されます。 | URP の深度・法線・不透明テクスチャから入力を作り直すか、URP の Deferred レンダラーとその G バッファー配置を使います。 |
| `Camera.onPreCull`、`Camera.onPreRender`、`Camera.onPostRender` のデリゲート | 登録したコードが実行されなくなります。 | `RenderPipelineManager.beginCameraRendering` または `endCameraRendering` に移してください。 |
| 即時描画する `OnRenderImage`（`Graphics.DrawMeshNow` など） | エフェクトが表示されません。 | コマンドバッファー（`CommandBuffer.Blit`、`DrawMesh`）で描画し、`ImageEffectGraphics.ExecuteCommandBuffer` で実行してください。 |
| カメラを描画する `OnRenderImage`（`Camera.Render`、ヘルパーメソッド経由も含む） | URP ではエフェクトを実行しません：自分のカメラのフレームの中では別のカメラを描画できず、フレームが真っ黒になるためです。 | 別のカメラは `OnPreRender` か `OnPreCull` で描画し、`OnRenderImage` には Blit の呼び出しだけを残してください。カメラのステンシルバッファーをテストする Blit も、URP ではそれを参照できません。 |
| ライトに付けた Built-in のディファードライティングイベントのコマンドバッファー | 表示されません。 | 対応する URP イベントのレンダラー機能を使ってください。 |
| Built-in の G バッファー（`_CameraGBufferTexture0`〜`3`）を読むシェーダー（スクリーンスペース GI など） | エフェクトはエラーなしで入力を失います：URP の Forward レンダラーには G バッファーがなく、URP の Deferred 経路は独自の G バッファーを別の配置（`_GBuffer0`〜`_GBuffer6`）で持ちます。 | URP の深度・法線・不透明テクスチャから入力を作り直すか、URP レンダラーを Deferred に切り替えて `UnityGBuffer.hlsl` に合わせて読み取りを書き直してください。 |
| 1 つのシェーダー内でテクスチャの異なる複数の GrabPass | シェーダーは変換されません。 | URP の Opaque Texture は 1 つです：キャプチャをまとめるか、1 つだけ残して 2 回読んでください。 |
| 1 つの SubShader に描画パスが 32 を超える | 変換されません。 | パスをまとめるか、一部を別の SubShader やマテリアルに移してください。 |
| パスが `CGINCLUDE` ブロックにあるシェーダーからの `UsePass` | 変換されません。 | パスをシェーダーにコピーしてください。 |
| Urpify にまだ対応するものがない組み込み include | 「Stopped: ... includes ...」と表示され、シェーダーは変換されません。 | include の関数を手作業で移植するか、レポートを送信でシェーダーを送ってください。 |
| Built-in のライト変数の一部を直接読む、頂点単位でライティングする、または色を返さない `ForwardAdd` パス | 変換されません。 | `UNITY_LIGHT_ATTENUATION` を使ってパスを書き直すか、URP の追加ライトのループに移してください。 |
| コンバーターが知らないシグネチャのライティング関数 | 変換されません。 | Built-in でドキュメント化されている `Lighting<Name>` のシグネチャのいずれかを使ってください。 |
| 固定機能パイプラインのパス（シェーダープログラムなし） | 変換されません：URP はプログラムのあるパスだけを描画します。 | パスを vert/frag プログラムとして書き直してください。 |
| Unity のコンバーターの前にファイルがバックアップにない Material Variant | 独自の値が Unity のコンバーターで失われます。 | そのファイルを保存する Urpify のステップで移行するか、値を設定し直してください。 |
| 変換後にコンパイルできないシェーダーやスクリプト | 元のファイルが戻され、コンパイラーのメッセージが検出結果に入ります。 | シェーダーパネルで結果を直して「名前を付けて保存」で保存するか、レポートを送信でシェーダーを送ってください。 |

## 変換されるが同一ではないもの

以下は変換されて動きますが、変換ではなく URP 自体による違いがあります。画像は
[URP で見た目が変わる点](urp-differences.md) にあります。

- **Opaque Texture を使う GrabPass**（既定）：URP は透明オブジェクトの前に画面をコピーするため、屈折に透明オブジェクトは
  映りません。後でコピーするには GrabPass のソースで「透明オブジェクトの後」を選んでください。
- **独自のライティング関数と ForwardAdd パス：** 作者の関数は、メインライトと各追加ライトについて 1 つのパスの中で、
  URP の影と減衰を使って実行されます。
- **Post-processing Stack v2 のブルーム：** URP のブルームになり、光はより柔らかく広がります。URP のブルームピラミッドは
  小さな明るい点を別の形で広げます。
- **Standard から URP Lit**（Unity 自身の変換）：私たちのテストシーンでは、フレームの最大約 7 % が異なります。
- **`OnWillRenderObject` の反射** は、カメラから見えるレンダラーについて、オクルージョンカリングなしで URP のカリングの
  前に呼ばれるため、壁の向こうの反射も描画されます。
