# ゲームを移行する

Built-in Render Pipeline のゲームを、見た目を変えずに URP に移したい場合の手順です。

## 始める前に

- プロジェクトをコミットしてください。Urpify は変更するものをバックアップしますが、最も信頼できる復元ポイントは
  コミットです。
- プロジェクトが Built-in でコンパイルでき、Play Mode に入れることを確認してください。Urpify はスクリプトの
  コンパイルエラーを検出結果として報告します：コンパイルエラーは Play Mode を、ひいてはキャプチャを妨げます。
- 比較するシーンを決めます：Project Settings > Urpify > 比較 > シーン。既定では Build Settings のシーンです。
- エフェクトが重要なシーン（ポータル、鏡、水、ポストエフェクト）に Migration Viewpoint をいくつか置きます。空の
  GameObject に `MigrationViewpoint` コンポーネントを追加し、カメラのように向けてください。EditorOnly タグが付いて
  いるので、ビルドには含まれません。

## スキャンして概要を読む

Window > Rendering > Urpify > **プロジェクトをスキャン**。概要は壊れるシーンから始まり、続いて壊れたアセットを誰が直すか
で数えます。

- **Unity のコンバーターと Urpify**：Unity の Render Pipeline Converter が更新する組み込みシェーダーと、その結果が誤って
  いて無料パッケージが後から直すケース。
- **Urpify Pro**：独自シェーダー、画像エフェクト、カメラスクリプト、コマンドバッファー、プロジェクター。
- **手動または未対応**：移行前からプロジェクトが壊れていた、URP に対応するものがない、または Urpify がまだ変換しない。
  [変換されないもの](not-converted.md) を参照してください。

左のリストは問題、修正、種類で絞り込め、ファイル名やルール ID で検索できます。**Pro なしで修正** は無料パッケージが扱う
ものを表示します。

## 移行する

**移行...** > **すべて実行**、またはステップごとに実行します。ファイルを変更するステップは、先にバックアップを取ります。
ステップの実行中はウィンドウに進行状況が表示され、どのステップも再実行できます。ステップの途中でエディターが閉じた場合は、
次にウィンドウを開いたときに、そのステップを再実行するかロールバックするかを提案します。

## 比較して確認する

**移行後をキャプチャして比較** のあと、**シーンを比較** を開きます。

- **同じ**：Standard から URP Lit への変換で調整したしきい値の範囲でフレームが一致します。
- **変化あり**：一部のピクセルが異なる、ある領域が大きく変わった（反射や光が消えたなど）、または再生中にシーンがエラーを
  記録しました。
- **新たなピンク**：オブジェクトがエラーシェーダーで描画されています。

変化したシーンは **差分を表示** で確認してください。差分の一部は移行ではなく URP によるものです：
[URP で見た目が変わる点](urp-differences.md) を参照してください。

最終レポート（**まとめ**）には、変換したファイルごとに段階が記されます：`自動`（実質的に同一）、`近似`（近いがピクセル
単位では同一でない）、`要確認`（変換済みだが Urpify 自身のテスト描画が元と異なる：確認してください）、そして手作業が必要
なもの。

## ロールバック

**すべてロールバック** でプロジェクトを最初のステップの前の状態に戻します。ステップの **ここまでロールバック** は、その
後のステップをすべて取り消します。移行後に自分で変更したファイルはそのまま残り、Console に一覧表示されます。

## ビルドパイプラインで

どのステップもコマンドラインから実行できるので、ビルドサーバーでブランチを移行し、シーンがピンクになったらビルドを
失敗させられます。[コマンドライン](cli.md) を参照してください。
