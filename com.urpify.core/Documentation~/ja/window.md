# Urpify ウィンドウ

`Window > Rendering > Urpify`。ウィンドウ自体の文章は短くしてあります。このページでは、アイコン、カウント、タグの意味を
説明します。ウィンドウのアイコンやカウントにマウスを乗せると、同じ説明が表示されます。

## 深刻度のアイコン

アイコンはそれぞれ形が異なるので、色だけが手がかりになることはありません。

| アイコン | 名前 | URP に切り替えた後に起こること |
|---|---|---|
| 塗りつぶした四角（ピンク） | ピンクになる | オブジェクトが URP のエラーシェーダーで描画されます。リリースビルドでは見えません。 |
| 塗りつぶした三角（琥珀色） | エラーなしで壊れる | エラーもピンクもありませんが、エフェクトが消えるか誤ります：ポータルが灰色の壁になる、水の泡が消える、ポストエフェクトが消える。 |
| 塗りつぶしたひし形（青） | 見た目が変わる | 描画はされますが、シーンが暗くなるなど目に見える違いがあります。 |
| 輪（灰色） | 見た目の変化なし | 何もする必要がないか、Unity のコンバーターがそのまま処理します。 |

リストの行、シーン、アセットは、最も深刻な検出結果のアイコンを表示します。

## ツールバーの下の帯

名前付きのグループに分かれた数です。移行前は `シーン` と `アセット` で、それぞれ深刻度ごとのアイコンと数が続きます：その深刻度のオブジェクトを含むシーンの数と、その深刻度を持つアセットの数です。シーンやアセットは該当するすべてのカテゴリで数えるので、数は重なります。キャプチャした後は、`キャプチャ済み` がフレームの結果（新たなピンク、変化あり、変化なし）を加えます。移行後は最初のグループが `結果` になります：修正済み、要確認、未対応。どの数もボタンです。選ぶとリストにはその数が数えるものだけが残り、もう一度選ぶとすべて表示されます。数にマウスを乗せると何を数えているかが、`最終スキャン` に乗せるとスキャンしたファイル数と時間が表示されます。

## シーンの判定

シーンには 2 つの判定があります。

- **静的**（スキャンによる）：シーンが使うすべてのものの中で最も深刻な問題。ピンクのオブジェクトがどのキャプチャフレーム
  にも映っていないことがあるため、静的なピンクと観測の「同じ」が並ぶこともあります。
- **観測**（移行前後のキャプチャによる）：最も悪いフレーム。各フレームには、変化したピクセルの割合と移行後のピンクの
  ピクセルの割合が表示されます。行にマウスを乗せると、平均差分と移行前のピンクの割合が表示されます。大きな変化領域
  （反射や光が消えたなど）が 1 つあれば、全体で変化したピクセルが少なくてもフレームは「変化あり」になります。移行後に
  シーンを再生している間に Console にエラーが出た場合も、最初のエラーを表示して「変化あり」になります。移行で直らなかった
  サイレントな破損をスキャンが予想していた場合（Unity のコンバーターのみ、Pro だけが直す破損に無料パッケージを使った場合、
  または Urpify が変換できなかった場合）に、フレームが同じに見えるときは、パネルがそう伝えます：差分マップを確認して
  ください。

移行前後のビューでは、線の左が移行前、右が移行後です。`差分を表示` は変化したピクセルに印を付けます：変化が大きいほど
ピクセルは赤くなります。

## 誰が直すか

概要は、壊れたアセットを誰が直すかで数えます。

- **Unity のコンバーターと Urpify**：Unity の Render Pipeline Converter と、その後に Urpify が実行する修正（どちらも無料
  パッケージ）。
- **Urpify Pro**（無料パッケージでは錠前付きの **Pro が必要**）：Pro のコンバーターだけが変換するシェーダー、スクリプト、
  コンポーネント。
- **手動または未対応**：移行前からプロジェクトが壊れていた、URP に対応するものがない、または Urpify がまだ変換しない。
  対処法は検出結果に書かれています。

リストの行は、そのアセットを誰が直すかを示します：`Unity`（Unity のコンバーター）、`Urpify`（無料の修正）、`Pro`（Urpify Pro。無料パッケージでは鍵と `Pro`）、`手作業`。ツールチップには結果の近さが出ます：元と一致する、元に近い、または変換済みだが見た目が違う（確認してください）。`修正するもの` フィルターは同じグループを選びます。移行後は、代わりにアセットがどうなったかを示します：`修正済み`、`要確認`、`未対応`。Urpify のコンバーターのステップの前はスキャンの見込み、後はそのステップが行ったことです。レポートにはコンバーター自身の段階（`自動`、`近似`、`要確認`、`未対応`、`手作業`）が残ります。

Urpify が変換するシェーダーは描画で確認されます：変換前に、そのシェーダーを使うプロジェクトのマテリアルを付けた球を
Built-in で描画し、変換後に URP で描画して、2 つを比較します。球の大部分が異なる場合もシェーダーは変換されますが、`自動`
ではなく `要確認` になり、画像の組は `Urpify/Reports/self-check/` に置かれます。「大部分」とは球の 25 % を超える部分です：
Unity 自身の Standard から URP Lit への変換は暗く彩度の高い色を最大約 20 % 変えますが、それは URP Lit の見た目であり、
誤りではありません。ピンク、または後ろにあるものを隠してカメラのクリアカラーを表示するオブジェクトは、大きさに関係なく
`要確認` です。

球では判断できないシェーダーもあり、それらは理由をレポートに記したうえで最大でも `近似` になります。シーン比較で確認
してください。

- マテリアルのない画面エフェクト（スクリプトが画面全体に適用する）
- `Hidden/` 以下の内部シェーダー（スクリプトが独自のデータで描画する）
- 時間（`_Time`）を読むシェーダー：Built-in の描画は変換前、URP の描画は変換後に行うため、アニメーションの別の瞬間を映す
  （ピンクと、描画が暗くなる場合だけを数える）

Unity 2022.3 では、`GrabPass` を持つシェーダーはプレビューカメラではなく、Game タイプの非表示カメラで描画されます：
URP 14 はプレビューカメラに Opaque Texture を渡さないためです。このカメラは URP Asset のレンダラー機能も実行します。

## 何が壊れるかを表示

概要と移行ウィンドウのステップの上にある `何が壊れるかを表示` は、何も直す前に、URP だけでプロジェクトがどうなるかを見せます：プロジェクトをバックアップし、Built-in でシーンをキャプチャし、URP をインストールし、Unity のコンバーターを実行し、シーンをもう一度キャプチャして結果を開きます。Urpify 自身の修正はまだ実行されていません。そのあと `Urpify で修正`（Urpify のコンバーター、キャプチャのやり直し、レポート）か `ロールバック` を選びます。無料パッケージでは修正は無料のものになり、結果には Urpify Pro が必要なものが示されます。

## ステップの順序

前のステップが終わっていないステップは実行できず、説明の下にその理由が出ます：移行前のキャプチャにはバックアップが、Unity のコンバーターには URP のインストールが、Urpify のコンバーターには Unity のコンバーターが（Keep Built-in support の場合を除きます。そのときプロジェクトは Built-in のままです）、移行後のキャプチャには移行前の画像と URP で描画されるプロジェクトが必要です。同じパイプラインで撮った 2 つのキャプチャは比較されず、比較するものがないと表示されます。

## 移行後の結果

Unity のコンバーターを実行すると、右側には概要の代わりに結果が表示されます：大事なことを 1 行で（例：`完了しました。シーンは切り替え前と同じに見えます`）、最も変化したシーンの移行前と移行後、そして対応が必要なものだけがそれぞれボタン付きで続き、修正済みのアセットは `自動で修正済み` にたたまれています。ウィンドウはステップのたびにプロジェクトをスキャンし直すので、リストには何が直って何が残っているかが出ます。Urpify がプロジェクトに追加するファイル（`Assets/Urpify/`、パッケージの `UrpCompat` フォルダー、`UrpSettingsCheck_*` スクリプト）はリストに出ません。

## シーンを比較

キャプチャした各シーンと、その結果を言葉で示します。シーンを選ぶと、その場でスライダーを使って画像を比較できます。`シーンを開く` でシーンが開きます。シーンが 1 つだけなら、比較は最初から開いています。ウィンドウは後からスキャンしても常に最新の比較を表示します。画像は画面に映るとおり、透明部分なしで保存され、設定の `キャプチャのサイズ` で別の指定がなければ Game ビューのサイズになります。

## ライセンスタグ

ヘッダーにライセンス（`MIT` や `CC-BY-NC-4.0` などの SPDX 識別子）を記したシェーダーは、名前の横にそれをタグで表示します。
変換したコピーは派生物であり、同じライセンスのままです。非商用ライセンス（`-NC`）は琥珀色のタグで示されます：そのような
シェーダーの変換コピーは販売できません。

## 環境光（シーンパネル）

Unity 6 では、スカイボックスから環境光を取り、ベイクしたライティングデータを持たないシーンを、プレイヤーはその光なしで
描画します。Built-in でも URP でも同じなので、シーンはエディターより暗く見えます。移行が原因ではないため、検出結果は情報
（輪のアイコン）です（Unity 2022.3 ではベイクしたデータがなくてもプレイヤーは環境光を受け取るため、Urpify はこうした
シーンを報告しません）。`環境をベイク` は、スカイボックスの環境光と反射だけをシーンのライティングデータにベイクし
（ライトマップはベイクせず、シーンの Auto Generate はオフになります）、プレイヤーをエディターと一致させます。事前に
プロジェクトのバックアップを取ります。同じ場所の `ベイクをロールバック`、または移行ウィンドウのロールバックで元に戻せ
ます。
