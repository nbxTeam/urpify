# シェーダーを変換する

シェーダーを書いたり保守したりしていて、計算式には手を入れずにその 1 つを URP に移したい場合の手順です。

## シェーダーを開く

次のどの方法でもシェーダーパネルが開きます。
- スキャン後、Urpify ウィンドウのリストでシェーダーを選ぶ
- Project ウィンドウでシェーダーを右クリック > Urpify > Analyze
- `.shader` ファイルを Project ウィンドウから、またはディスクから直接 Urpify ウィンドウにドラッグする。ディスクのファイル
  はその場所のままで、何もインポートされません。

## コードを読む

**コード** タブでは、左に元のシェーダー、右に変換後のシェーダーが表示されます。変更された行には印が付き、マウスを乗せると
変更理由が表示されます：URP 用にタグを付け直したパス、置き換えた Built-in の include、SRP Batcher のために
`UnityPerMaterial` に移したマテリアルプロパティなど。

Urpify が変えるもの、変えないもの：
- シェーダー名とプロパティ名はそのままなので、マテリアルは動き続け、値も保たれます。
- 作者の関数（`surf`、`vert`、`frag`、ライティング関数、ヘルパー）はそのままコピーされます。変わるのは配線だけです：
  シェーダーがライト、影、深度、画面の画像、行列をどう受け取るか。
- `UnityObjectToClipPos`、`_LightColor0`、`UNITY_LIGHT_ATTENUATION` などの Built-in の名前は、それらを URP に対応付ける
  Urpify の互換ライブラリ `BirpCompat.hlsl` によって引き続き使えます。

**結果を編集** で変換後のコードを変更し、マテリアルが使うキーワードで **コンパイル** できます。エラーは該当する行に表示
されます。**名前を付けて保存...** は結果を新しいファイルに書き出し、**変換** は元のファイルを `Urpify/Backup/ShaderPanel`
にバックアップしたうえで置き換えます。

コンバーターが最後まで進めない場合、右の列には止まった行と理由付きの読み取り専用の下書きが表示されます。下書きは保存して
手作業で仕上げられます。変換ボタンと移行がそれを使うことはありません。

## プレビュー

**プレビュー** タブは、球、立方体、平面、または自分のメッシュにシェーダーを描画します。Built-in と URP の両方で、同じ
マテリアルの値を使います。**表示** で Built-in、URP、スライダー付きのカーテン、差分マップを切り替えます。**ライトの向き**
でメインライトを回します。マテリアルのプロパティを変えると、両方のプレビューが追従します。

Built-in のプレビューは、描画の瞬間だけレンダーパイプラインをオフにして戻します。これは 1 回の呼び出しの中で行われます。
失敗した場合、パネルは **キャプチャから** に切り替わり、代わりにシーンのキャプチャを表示します。すでに変換済みのファイル
では、Built-in 側は移行のバックアップから元のシェーダーを描画します。

## 結果を確認する

移行が変換するシェーダーは、描画でも確認されます：そのシェーダーを使うプロジェクト自身のマテリアルを付けた球を、変換前に
Built-in で、変換後に URP で描画します。球の 25 % 以上が異なる場合、シェーダーは変換されますが `要確認` になり、画像の組
は `Urpify/Reports/self-check/` に保存されます。変換後のコードがコンパイルできないシェーダーは元に戻され、報告されます。

## 変換が止まったとき

パネルには、コンバーターが扱えない構成要素と対処法が表示されます。[変換されないもの](not-converted.md) にすべて記載されて
います。変換できるはずのシェーダーが変換されない場合は、**レポート > レポートを送信...** でシェーダー、その include
ファイル、検出結果をアーカイブにまとめます：保存するか、私たちに送ってください（送信を押したときだけ送られます）。

## シェーダーのライセンス

ファイルのヘッダーにライセンスが書かれている場合、パネルに表示されます。変換したコピーも同じライセンスのままです。
非商用ライセンスの場合は販売できません。
